# GAS(Google Apps Script) 백엔드

이루리 정산 시스템의 서버 코드입니다. 앱(`adjustment-system.html`)이 이 코드를 통해
구글 스프레드시트·드라이브를 읽고 씁니다.

- 스프레드시트: `강사DB`, `센터DB`, `제출데이터`, `제출이력`, `강사계정`, `영수증`, `접속현황`, `가입대기`, `시스템설정`
- 드라이브: `이루리/정산스냅샷` (월별 정산 JSON), `이루리/이루리_영수증`

## 붙여넣는 방법

1. Apps Script 편집기를 엽니다 (스프레드시트 → 확장 프로그램 → Apps Script).
2. **기존 코드를 전부 지우고** `Code.gs` 내용을 붙여넣습니다.
3. 맨 위 `SPREADSHEET_ID` 한 줄을 실제 값으로 바꿉니다.
   (이 저장소는 공개라서 비워뒀습니다. 스프레드시트 주소의 `/d/` 와 `/edit` 사이 문자열)
4. **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**
   ⚠️ '새 배포'가 아니라 **기존 배포를 수정**해야 URL이 그대로 유지됩니다.
   URL이 바뀌면 앱이 서버를 못 찾습니다.

## 되돌리는 방법

- **가장 쉬움**: Apps Script 편집기 왼쪽 `⏱ 버전 기록`에서 이전 버전을 선택해 다시 배포.
- 또는 이 파일의 이전 깃 커밋 내용을 붙여넣기.
- 버전·지문 값은 **스크립트 속성**에만 저장되므로 시트 데이터에는 아무 영향이 없습니다.

## 속도 개선(2026-08)이 하는 일

앱이 느렸던 가장 큰 이유는 **안 바뀐 데이터를 매번 통째로 주고받은 것**입니다.
구글 앱스스크립트는 한 사용자의 요청을 사실상 한 줄로 세워 처리해서,
요청 하나하나가 그대로 대기 시간이 됩니다.

| 무엇 | 전 | 후 |
|---|---|---|
| `getCenters` 응답 (안 바뀐 경우) | 약 29,000 B + 시트 278행 읽기 | **40 B, 시트 안 읽음** |
| `syncCenters` (내용 같은 경우) | 시트 3,906칸 다시 쓰기 | **0칸 (건너뜀)** |

동작 방식:

- 강사DB·센터DB가 **실제로 바뀔 때만** 버전 번호가 1 올라갑니다.
- 앱이 `?v=<가지고 있는 버전>`을 같이 보내고, 서버 버전과 같으면
  시트를 읽지도 않고 `{ok:true, unchanged:true}`만 돌려줍니다.
- 같은 내용을 또 저장하라고 오면 시트 쓰기를 통째로 건너뜁니다.
  (단, 누가 시트를 손으로 고쳐 행 수가 달라졌으면 다시 씁니다)

### 호환성

- **앱만 먼저 배포**해도 안전합니다. 옛 서버는 `version`을 안 주므로 앱이 버전을 저장하지 않고, 예전처럼 매번 전체를 받습니다.
- **서버만 먼저 배포**해도 안전합니다. 옛 앱은 `v`를 안 보내므로 항상 전체를 받습니다.

### 문제가 생기면

Apps Script 편집기에서 `resetDbVersionCache` 함수를 직접 실행하세요.
버전·지문이 초기화되어 모든 앱이 다음 요청부터 전체 데이터를 다시 받습니다. (데이터는 그대로)

앱 쪽에서는 상단 **동기화 버튼**을 누르면 저장된 버전을 지우고 전체를 다시 받아옵니다.

## 바뀌지 않은 것

- 강사 급감 차단(`DB_DROP_BLOCK`), 2건 이상 변경 차단(`bulk`), 일일 자동 백업
- 강사 모드에서 남의 계좌 정보 가리기
- 월별 스냅샷의 빈 데이터 거부·단조성 검사·롤링 백업(.bak1/.bak2)
- 로그인/비밀번호(해시) 처리
